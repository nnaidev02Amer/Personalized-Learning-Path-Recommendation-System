# AI / ML models (Phase 5)

All models are trained from the SQLite database by `backend/app/ml_service.py`
(≈5–10 s, in a background thread at API start-up, or `POST /api/ml/retrain`).
The model code is in `ml/` and has no database dependencies.

| Feature | Module | Method |
|---|---|---|
| Course recommendations | `ml/recsys.py` | Content-based (TF-IDF of course text + topic affinity + preferred format), collaborative (item-kNN with shrinkage over implicit feedback), hybrid (min-max blend, weight α tuned on held-out students; leans on content for cold-start), popularity baseline. Only unlocked, untaken courses are recommended; every item carries reasons. |
| Skill mastery / gaps | `ml/knowledge_tracing.py` | Bayesian Knowledge Tracing with an **individualised prior**: a skill the learner has not been tested on starts from their accuracy on other skills, shrunk toward the population (shrinkage strength fitted; classic BKT is the special case). Parameters are shared across skills and fitted by maximum likelihood over a grid bounded by the standard degeneracy constraints (guess ≤ 0.3, slip ≤ 0.25, learn ≤ 0.3); among fits whose likelihood is statistically indistinguishable from the best, the most conservative is used. Gaps = assessed skills below 60% mastery, plus untested skills of active courses. |
| Adaptive difficulty | `ml/bandit.py` | LinUCB contextual bandit; arms = Beginner / Intermediate / Advanced; reward = quiz score in [60, 90) ("productive challenge"); warm-started offline, updated online after every quiz submission. |
| Performance prediction | `ml/performance.py` | **Ability-anchored gradient boosting**: an empirical-Bayes (Beta-Binomial) ability estimate from every earlier answer (shrinkage strength estimated from the data) plus a small, heavily regularised boosted residual on point-in-time features (`ml/learner_state.py`: level, retake, format match, BKT mastery, topic form, trend) with monotonic constraints, so a better record can never lower the prediction. |
| Learning style | `ml/style_model.py` | Decision tree on profile + behaviour (time share per content format, scores, completion). |
| Assistant | `backend/app/assistant.py` | Intent detection + templates over the model outputs; optional Claude API (official `anthropic` SDK, `claude-opus-5-5` by default, low effort, server-side refusal fallbacks enabled) grounded on the same JSON context, with automatic fallback to the built-in answer. |
| Statistics | `ml/stats.py` | Paired bootstrap 95% CI for every model-vs-baseline comparison. |

## Evaluation results (seeded database, fixed seeds — reproducible)

A model is called **better** only if the paired-bootstrap 95% CI of its
improvement over the strongest baseline lies entirely above zero.

### Recommendations — leave-last-out, 50 test students (α tuned on the other 50)

| Method | NDCG@5 (unlocked, ~4.6 candidates) | NDCG@5 (all untaken, ~18.4 candidates) |
|---|---|---|
| Hybrid (α = 0.75) | **0.726** | 0.679 |
| Collaborative (item-kNN) | 0.719 | **0.684** |
| Content-based | 0.598 | 0.216 |
| Popularity (baseline) | 0.690 | 0.627 |
| Random (analytic) | 0.604 | 0.163 |

Hybrid vs popularity: +0.036 [−0.032, 0.103] and +0.053 [−0.032, 0.139] → **not significant**.
Content-based alone is weak here: the synthetic histories are driven mostly by
prerequisites and course popularity. A wider tuning grid (content weights +
popularity prior, 135 combinations) was tried and **overfit** (tuning-half NDCG
0.691 → 0.739, test-half 0.70 → 0.63), so only α is tuned.

### Bayesian Knowledge Tracing — 30 held-out students, 920 answers

| Model | AUC | Log-loss |
|---|---|---|
| BKT, individualised prior (p_init 0.9, p_learn 0.3, p_slip 0.15, p_guess 0.3, prior strength 16) | **0.626** | **0.489** |
| Global accuracy (best baseline by log-loss) | 0.500 | 0.497 |
| Student running accuracy | 0.603 | 0.517 |
| Per-skill accuracy | 0.531 | 0.606 |

Δ log-loss vs the best baseline +0.0082 [−0.0008, 0.0173] → **not significant**
(but now clearly better than before the fix: AUC 0.541 → 0.626, log-loss 0.497 → 0.489).
Each skill appears in one course, so students have only 1–8 answers per skill;
what carries signal is *how this learner answers in general*, hence the
individualised prior. On data generated by a BKT process the implementation
still recovers the parameters and beats the baseline (`tests/test_ml_models.py`).

**Known limitation.** BKT credits recent correct answers: a learner who fails a quiz and then
answers every question correctly on the immediate retake is judged to have learned the skill
(e.g. 0 of 4, then 4 of 4 → mastery ≈ 0.86–0.95 although overall accuracy is 50%). Repeated
*wrong* answers, however, now keep mastery below the 0.6 threshold (0 of 3 → ≈ 0.38).

### Performance prediction — last 20% of attempts by time (149)

| Model | MAE | RMSE | R² |
|---|---|---|---|
| Ability-anchored gradient boosting | **15.9** | 20.5 | 0.06 |
| Ability anchor alone (no booster) | 16.6 | 20.6 | 0.05 |
| Student's prior mean | 17.3 | 22.6 | −0.13 |
| Training mean | 17.3 | 21.3 | −0.01 |

MAE improvement vs the best baseline 1.34 points [0.20, 2.52] → **significant**; the
boosted residual adds 0.68 [0.08, 1.32] over the ability anchor. Shrinkage strength κ = 16
pseudo-answers (estimated). Prediction now follows the learner's record: 0 of 12 answers
correct → ≈ 48, 6 of 12 → ≈ 69, 12 of 12 → ≈ 90 (before: a learner with three 0% attempts
was predicted 83–90 "likely").

### Adaptive difficulty — last 20% of attempts by time (149)

LinUCB reward-model Brier 0.233 vs 0.235 for the per-level average → **not
significant** (Δ 0.0023 [−0.008, 0.012]). Replay estimate 0.41 vs 0.37 logged
reward on 44 matched events — biased, because historical difficulty was not
randomised (455 Beginner / 131 Intermediate / 8 Advanced training attempts).

### Learning style — 5-fold nested CV, 100 students

Decision tree 23% ± 9 vs 32% majority baseline (25% chance) → **not reliable**.
The API returns the prediction with `reliable: false` and the UI uses the
self-reported style. (The labels in `sample_data.csv` are independent of every
recorded feature — see `PHASE1_ANALYSIS.md`.)

## Honest summary
The models are real, are evaluated against baselines on held-out data, and work
on data that contains the signal they look for (unit tests). On the seeded
database, **none significantly beats its strongest simple baseline**. The
training data is mostly synthetic; as real usage accumulates, retrain from the
Model Evaluation page and the verdicts update automatically (UI text is driven
by the stored evaluation, not hard-coded).

## Known limitations (read before relying on an output)
* **No model significantly beats its strongest baseline on the seeded data** (tables above).
  Treat outputs as illustrations of the pipeline, not as validated advice.
* **BKT mastery is dominated by its prior.** The fitted parameters sit at the edge of the
  grid (P(init) 0.9, P(learn) 0.45), i.e. the data is best explained by "most skills are
  already known". A student with 1 of 2 answers correct can therefore show ~96% mastery, and
  gaps are rarely flagged. The UI always shows the raw answer count and accuracy next to the
  estimate. Per-skill evidence is thin because each skill appears in one 4-question quiz.
* **Difficulty bandit** was trained on 455 Beginner / 132 Intermediate / 8 Advanced attempts,
  so its Advanced estimate is very uncertain; the card shows when it is exploring.
* **Learning-style model** is flagged unreliable; the app personalises with the self-reported style.
* **Recommendations** never beat popularity significantly; with ~4.6 unlocked candidates,
  hit rate is ~1 for every method, so only NDCG/MRR are informative.
* **Retraining** (Model Evaluation page) re-runs every evaluation on the current database; the
  numbers above are for the freshly seeded database and change as real usage is added.
* **Insufficient data**: with fewer than 10 students with 2+ enrolments or 30 quiz attempts the
  AI endpoints return 503 `ml_insufficient_data` instead of training on too little data.

## Synthetic data used for training
`backend/app/seed/generator.py` simulates per-question quiz answers:
P(correct) = σ(ability + skill strength − 0.6·(level−2) + trend·day + 0.5·retake).
Ability is solved so each student's mean score matches `AverageScore` from
`sample_data.csv`; the total of correct answers is fixed, so the mean is within
50/N points (measured mean |Δ| = 1.3, max 11.9). About 35% of quizzes are retaken.
